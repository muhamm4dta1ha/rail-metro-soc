# Scenario C — Controlled Service Disruption

Run `src/attacks/scripts/run_lab.ps1 -RoeApproved -Campaign -Scenarios C` inside the approved lab workflow. The temporary DMZ client sends sequential GET /api/arrivals to PIS 10.60.20.10:8080. It uses one deadline for low-rate, increased-rate and recovery phases. A separate OCC baseline keeps the low rate throughout. The run stops sending increased traffic automatically; no service settings are changed.

Eleven successful attack runs recorded 205 HTTP 200 responses, no failures and no timeouts. The demonstration rose from 1.33 to 6.67 observed requests/s and returned to 1.33; mean phase latencies were 15.12, 3.58 and 2.76 ms. The observed indicator was a rate spike. See the [report](M2_Attack_Simulation_Report.md) for paths and the two earlier attempts excluded from the handoff. Use `http.response && ip.dst == 10.60.20.99` in a Wireshark I/O graph. Compare rates to baseline, then examine status and latency before classifying an availability incident.
